## Follow-up review fixes (same date, rerun of affected checks only)

- **Reverse race (test 2b) rewritten for genuine two-request racing.** Both gates are installed up front with baselines captured before any sort. The test waits for **both** intended requests to arrive at their fixture gates (`waitForGateArrival` for furthest, then soonest) and asserts neither response has been sent (`responsesSent`, counted fixture-side after the gate passes) before releasing either. It then releases the **newest (soonest)** first, awaits explicit fixture delivery (`waitForResponsesSent`) plus settled URL/selection/cards/`aria-busy` cleared, and asserts the older (furthest) gate is still unreleased and its response still undelivered. Only then is the older response released; its fixture delivery is awaited, payload body-reads are awaited, and final URL/selection/exact cards are re-asserted. Evidence from the final run: `gateArrivals=[["soonest",10],["furthest",3]]; responsesSent=[["soonest",10],["furthest",3]]` (counts cumulative across the suite; deltas against the in-test baselines are what the assertions check), and the recorded card-state sequence contained exactly one state, the soonest order. **The cached-state scenario in the review did not occur**: the newest request genuinely reached its gate while the older was held, so no distinct uncached target was needed; had `waitForGateArrival` timed out, the test would have failed loudly instead of passing.
- **Observer wording and blanking.** The observer (MutationObserver + 25 ms sampling) records **observed DOM states, not every React commit** — a commit that never reaches the DOM or is replaced between samples would not appear. It now records empty sequences too (previously skipped), and both race tests clear the recording once the initial catalogue shows 6 cards, then assert every subsequently recorded state has exactly 6 cards, so unexpected blanking or partial renders fail.
- **Benchmark payload reads.** All RSC response-body reads are tracked and awaited (`Promise.all(bodyReads)`) before byte totals are reported, for both the initial/prefetch phase and the sort phase. Bodies the browser did not retain (Playwright/CDP: "No data found for resource with given identifier", seen on prefetch responses) are counted in the new `unreadableRscBodyCount` field instead of being silently counted as 0 bytes; `rscPayloadBytes` is therefore readable-bytes only. Throttling description corrected to match the actual CDP configuration: 100 ms latency, 1.5 Mbps download, 750 kbps upload, 4x CPU (an earlier comment claimed 562.5 kb/s / 500 ms, which never matched the code).
